Executive Summary

Agent plugin marketplace 已形成可观测的生态维护问题对 Claude Code marketplace 的大样本研究显示，plugin 不只是一次性自然语言配置。Instruction 与 script 在关键目录中会发生功能性 co-evolution，意味着平台扩展机制需要新的依赖检测、版本治理与 complementor support。
平台 attention policy 会同时改变权重与披露选择当两方只能呈现真实证据但可选择性沉默时，增加一方 exposure 会提高其影响，却降低其发言频率并提高内容极端性。准确设计的目标不是表面 voice balance，而是两方 directional tail moments 的平衡。
AI agent 治理的共同方向是把约束移出 agent reasoning两项安全原型分别把 authorization / data exposure 放到 tool boundary，把跨组织 accountability 放到可离线核验的 evidence bundle；结果支持 bounded technical claims，但不能证明端到端 noninterference 或真实组织部署效果。

On the Maintenance and Co-evolution of Agent Plugins: An Empirical Study of Claude Code Plugin Marketplaces

Ahmed Hereiz、Yingzhe Lyu、Hao Li、Bram Adams、Ahmed E. Hassan · Queen’s University · arXiv 2608.28497

背景及重要性Agent plugin marketplace 把 skills、commands、hooks、agents 与 tool connectors 交给第三方开发者。与传统 package 不同，核心 functionality 可能存放在自然语言 instruction 中，因此生态治理不能只复用 source-code maintenance 指标。
文章做了什么和怎么做作者使用 GitHub Code Search 识别 marketplace manifest，经过 repository、star 与 local-path filters，构建 1,926 个仓库、2,018 个 marketplaces、8,351 个 plugins 和 77,773 个 plugin-touching commits 的数据集，再结合 commit classification、manual coding 与 association-rule analysis。
最简单结论该生态快速增长且高度 AI-assisted；多数 component type 可独立维护，但 skill 目录中的 scripts 与 agent-facing Markdown 常有功能性依赖，接口、内部逻辑和变量变化必须同步更新 instruction。
  • Plugin-touching commit activity 在 2025 年 10 月 launch 后六个月内增长 8.8 倍，61.3% 的 plugins 面向 Software Engineering tasks。
  • Feature commits 占 39.6%，高于论文所用传统 OSS benchmark 的 17.2%；Claude co-author heuristic 识别出 34.9% commits，作者强调这是 AI involvement 的 lower bound。
  • 对 700 个 commits 的 manual coding 发现 docs、perf、style、refactor 在 agent plugin 中与传统含义明显不同，特别是 docs 经常修改 inference-time instruction。
  • 跨 component 的 association rules 多数 lift 小于 1；真正稳定的 above-chance coupling 出现在 skill 内部的 script 与 Markdown file types。
  • 64 个 co-change pull requests 的人工样本中，50 个具有功能性 coupling；主要机制是 interface change、internal logic change、variable/version synchronization 与 repository restructuring。
研究设计、样本与识别边界
环节可核验内容
Repository discovery2026-04-02 通过 GitHub Code Search 查询 marketplace manifest，获得 11,254 个 raw references；按 repository full name 去重为 10,646 个 repositories，再以至少 10 stars 过滤为 1,926 个。作者另用 5 与 25 stars 检查 qualitative stability。
Plugin sample解析 2,018 个 marketplace entries 和 9,565 个 raw plugins；剔除 external-path、duplicate、blank-source 与 unresolved local path 后保留 8,351 个 plugins。
Commit data克隆完整 Git histories，仅保留触及 plugin components 的 commits，共 77,773 次、3,948 位 unique authors；median 为每 repository 13 次。
Commit classification51,141 个 commits 由 Conventional Commits prefix 分类；其余 26,632 个由 GPT-5-mini 分类。两个独立 385-commit validation samples 的 agreement 分别为 92% 和 76.4%。
Manual coding按 commit type stratified sample 700 个 commits，两个作者 open coding，Cohen’s kappa 为 0.671；LLM rubric scaling 另做 validation。
Co-evolution在 748 个拥有超过 10 个 merged PRs 的 repositories 中分析 10,679 个 plugin PRs；skill 内部另分析 13,587 个 PRs。Script–Markdown taxonomy 来自 64 个 PRs 的人工编码，kappa 为 0.74，再扩展到 259 个 PRs。
识别边界这是单一平台生态的 observational repository study，不识别 marketplace policy 的 causal effect。Star threshold、GitHub-only discovery、single-run LLM labels 与可见 co-author trailers 都限制 generalizability 和测量精度。
主要结果与平台含义

结构与维护：34.4% 的 plugins 同时包含多种 component types。Agent-facing natural-language artifacts 不是普通 documentation：一项 script interface、默认值或 model identifier 变化，会要求对应 instruction 同步变化，否则 agent 可能按旧接口行动。

Co-evolution：skills 与其他 component types 的 co-change confidence 至少为 43.2%，但 component-level lift 多数低于 1。进入 skill directory 后，script–Markdown lift 为 1.37 至 1.58；64 个人工样本中的 78% 存在功能性 coupling。该层级差异说明生态风险藏在 package 内部的跨 artifact contract，而非仅在 component 共现。

治理含义：平台可考虑提供 schema-aware dependency checks、instruction–implementation consistency tests、version migration support 与 marketplace maintenance signals。论文没有直接测试这些治理工具，因而这些是由结果支持的设计方向，不是已验证 intervention。

Countervailing Curation: Strategic Disclosure and the Design of Attention

Qian Cao、Yifei Sun · University of International Business and Economics · arXiv 2608.27903

背景及重要性平台、编辑或法庭常在无法强制 complete disclosure 时分配 attention。即使证据不能伪造，advocates 仍可选择哪些真实观察进入 public record，因此 equal exposure、equal speech 与 accurate decision 并不等价。
文章做了什么和怎么做论文建立 designer、两个方向相反的 senders 与 selection-naive receiver 的 disclosure game。平台先分配 exposure；senders 在观察完整 evidence profile 后同时选择披露集合；receiver 对已显示证据与固定 benchmark 做 weighted average。
最简单结论Finite pool 中所有 equilibrium 都产生同一个 action / disclosure cutoff。增加一方 attention 会让该方说得更少、内容更极端、但影响更大；correct attention 取决于双方 favorable-tail moments，而不是最终可见的发言数量。
  • 每个 finite evidence pool 都有唯一 equilibrium action；向上倡导者披露 cutoff 以上证据，向下倡导者披露 cutoff 以下证据，ties 不影响 action。
  • Large pool 中 public narrative 随 upward attention share 严格上升；更薄的 marginal visible record 会放大 attention leverage。
  • 已知状态时，唯一 correct share 平衡两方 directional tail moments；拥有更大 favorable-tail capacity 的 camp 应获得更少 attention。
  • Representation paradox：更多 exposure 使获益方单项披露概率下降、披露值更极端，同时使对方披露概率上升。
  • 未知状态时，单一 share 只有在 state-contingent target 恒定时才能消除所有 bias；否则 ex ante optimum 是各状态目标之间的 weighted compromise。

决策平台选择 Sender 1 的 total potential exposure share；两个 senders 同时选择 disclosure sets；receiver 选择一维 action。

结果含义
Theorem 1Finite pool 的 balance function 有唯一 zero。所有 pure 或 mixed Nash equilibria 都产生同一个 action；Sender 1 显示 cutoff 以上 evidence，Sender 2 显示 cutoff 以下 evidence，只有 cutoff ties 可产生无关紧要的 strategy multiplicity。
Assumption 1给定 state，两组 evidence 在各自 camp 内 i.i.d.、跨 camp independent、atomless、interior density 正且连续，并且两组 mean 都等于 state；variance、skewness 与 tails 可以不同。
Proposition 1Anchor 消失、单项 weight 消失且 attention share 收敛时，finite cutoff 收敛到唯一 large-pool narrative；该 narrative 对 Sender 1 attention share 严格递增。
Theorem 2若平台知道 state，唯一 correct share 等于 Sender 2 downward tail moment 占两方 favorable-tail moments 之和的比例。Equal attention 只在两方 tail moments 相等时正确。
Proposition 2提高 Sender 1 attention：action 上升；Sender 1 的 per-item disclosure probability 下降、displayed evidence 更极端；Sender 2 disclosure probability 上升。
Proposition 3若 empty slot 仅以小于 full weight 的 benchmark value 部分填补，上述 feedback 保留；full imputation 时 cutoff 固定在 benchmark，disclosure frequency 不再随 attention 变化。
Theorems 3–4未知 state 时，optimal fixed share 位于 state-contingent targets 的最小值与最大值之间，并平衡 marginal distortions；finite-pool exact correction 可分为 selection-induced cutoff bias、fixed benchmark 与 sampling variance。
r*(θ)=Γ2(θ)Γ1(θ)+Γ2(θ)State-contingent correct share；两项 Γ 分别是两方在正确 action 两侧的 favorable directional tail moments。

Empirical predictions：在 attention 的 conditionally exogenous variation 下，模型联合预测 receiver action 上升、获益方发言率下降、对方发言率上升、获益方 displayed content 更极端。作者明确指出，这些 sign restrictions 不是 unique identification，平台规则或 evidence composition 同时变化也能产生相似 pattern。

证据边界：这是 stylized mechanism model，不是平台 field experiment。结论依赖 verifiable evidence、exclusive pools、nontransferable empty exposure、selection-naive averaging 与 directional conflict。

If Agents Were Angels, No Governance Would Be Necessary: Out-of-Band Policy Enforcement at a Trusted Tool Boundary

Marc Millstone、Tyler Akidau、Johannes Brüderl、Marat Pekker · Redpanda Data · arXiv 2608.27646

背景及重要性给 agent 一个人类 credential 会继承可访问范围，却不会继承人类在界面中逐条判断的工作方式。Prompt-based guardrail 还要求同一个 fallible reasoner 同时解释任务、吸收不可信内容并执行自身限制。
文章做了什么和怎么做作者提出 Out-of-Band Policy Enforcement，将 operation / resource authorization、argument shaping、record / field filtering、redaction、masking 与 semantic gating 放在 trusted tool boundary；并用 Cedar policy core、Jira / ServiceNow mocks、四个模型和 adaptive red-team tasks 评估。
最简单结论在受控 prototype 中，tool boundary 显著减少 protected data 进入 context 或 forbidden effects 完成；但它不保证全局 noninterference，agent 仍可能通过 row counts 或组合信息重构秘密。
  • Data owner policy 定义 maximum grant，agent-specific policy 只能进一步缩小；作者形式化证明在条件成立时 match order 不改变 plan，agent tier 不能扩大 owner ceiling。
  • Benchmark 共 3,621 trials，主要比较中的 deterministic trace-failure rate 从 57.6% 降至 0.2%；cluster-weighted reduction 为 41.2 percentage points。
  • Unweighted standalone fulfillment 从 79.1% 降至 60.9%，但 paired cluster-weighted safe-useful completion 上升 21.8 points，显示 protection 与 capability 不能只看单一 completion metric。
  • 四个 final answers 仍精确重构未进入 context 的 value，另有 trial 把 filtered row count 当作 oracle；field removal 只支持单次执行的有限保证。
  • Production write controls、durable approval、temporal policy 与 aggregate policy 不在本次 evaluation 范围。
Evaluation design 与主要结果
维度可核验内容
System简化 HTTP proxy prototype，Cedar typed policy core；在 backend call 前 authorize / shape，在响应后 filter / redact / mask，并可按 arguments 或 external state deny / defer。
TasksControlled Jira 与 ServiceNow mocks；20 个 response-adaptive red-team tasks；四个 agent models。
Design比较 Prompt only 与 Prompt + full OBPE；另做 raw / prompt rules、operator ladder 和 output reviewer 对比。每个 trial 隔离状态，避免前一次执行污染。
Primary outcomeDeterministic trace failure：protected data 进入 agent context、exact protected value 出现在 answer，或 forbidden backend effect 完成。
Results3,621 trials；primary contrast 57.6% 降至 0.2%。同权 standalone fulfillment 下降，但 paired safe-useful completion 上升。结论需按各比较的 weighting 与 judge definition 阅读。
ThreatsMocks、有限 models / tasks、synthetic operators、reconstruction attacks、row-count oracle，以及未覆盖 durable human approval 与 temporal / aggregate controls。

组织含义：Least privilege 不能只等同于 OAuth scope；组织还需要 assignment-level purpose、record / field exposure 与 approval state 的 deterministic enforcement。该论文支持 infrastructure-level governance 的 feasibility，而非证明真实企业部署已达到同样风险下降。

Offline-Verifiable Accountability for Cross-Organization Agent Messaging: A Preserved Evidence-Bundle Approach

Adil Alshammari、Hayretdin Bahsi · Northern Arizona University / Majmaah University / Tallinn University of Technology · arXiv 2608.28542

背景及重要性跨组织 agent workflow 的事后争议可能发生在 live systems 已不可用、由单方控制或不再被共同信任时。普通 logs 难以同时证明 message authorship、append-only continuity、delegated authority 与 explicit receipt。
文章做了什么和怎么做论文定义按 workflow event 保存的 evidence bundle，并让 policy-controlled offline verifier 逐项核验 sender authentication、log commitment、witnessed checkpoint、continuity、delegation 与必要时的 receiver-signed receipt。
最简单结论Prototype 能按 policy 对 bounded claims 做离线 evidence-sufficiency judgment；更强 assurance 增加 verifier latency。Accept 不能被解释为 delivery、semantic correctness 或 workflow completion 的普遍证明。
  • Receipt 只有在 policy 要求且 bundle 含 explicit receiver-signed evidence 时才成立；transport、storage 或 log inclusion 本身不能推出 receipt。
  • Evaluation 覆盖 300 个 complete workflows 和 1,200 个 valid preserved bundles。
  • Checkpoint-context anchoring 是当前 prototype 中 verifier-side latency 最高的环节；delegation 与 workflow-prerequisite evidence 也增加 steps。
  • 17 类 targeted negative-evidence mutations 均被拒绝，未观察到 false acceptance；这属于 diagnostic suite，不是 exhaustive fuzzing。
  • Absolute latency 不是生产常数，evaluation 未覆盖 network delay、organizational key management、independent witness availability、long branching workflows 或 endpoint compromise。
Evidence classes、evaluation 与 claim boundary
层面可核验内容
Evidence bundle保存 sender signature、canonical payload binding、authenticated log inclusion / checkpoint、append-only continuity、witness evidence、delegation capability、workflow prerequisites，以及 policy 要求时的 receiver receipt。
Verifier semanticsSelected policy 决定必须通过哪些 predicates，也决定 Accept 最多支持哪类 evidence-level claim。
Prototype data300 个 paired workflows、每个四类 events，共 1,200 个 valid bundles；另做 policy profile、event requirement 与 negative-evidence experiments。
Latency pattern前三类 core logged-message events median 约 400 ms；含 delegation / prior-event checks 的 submit-claim event median 约 680 ms。作者强调这是 prototype 内部的 relative attribution。
Negative testsCorrupt payload、Merkle path、checkpoint、continuity proof、capability binding、witness、workflow prerequisite 与 context anchoring 等 targeted cases 全部拒绝。
边界Valid bundle 不证明 endpoint correctness、delivery、semantic correctness 或 workflow completion；缺少 bundle 也不构成 underlying fact 不存在的证明。

组织含义：跨组织 agent network 需要事前定义 dispute-specific evidence policy，并保存足够 artifacts 供独立复核。更强 accountability 不是免费增加，它带来证据生产、保存与 verifier latency 成本。

How Much Can AI Understand? Toward AI-Assisted Sensemaking of Collaborative Discussion in Groups with Shared History

Soobin Cho、Mark Zachry、David W. McDonald · University of Washington · arXiv 2608.27799

背景及重要性长期在线社区的讨论嵌在 norms、hierarchies、participant histories 与 relationships 中。只总结 argument text 的 AI 可能遗漏为何某句话重要，甚至制造 false consensus。
文章做了什么和怎么做基于两项 experienced Wikipedia editors 研究：一项观察 unassisted sensemaking，另一项使用 LLM-assisted web prototype。作者据此提出覆盖六类 information 与人机分工阶段的 AI-Assisted Sensemaking Model。
最简单结论系统做得越多，用户 burden 越低，但用户越依赖其判断。设计应让 AI 支持早期 search、extraction、prioritization 与 connection，把最终 Build Case / Tell Story 留给人，并保留 original data 与 rationale。
  • 需要同时表示 argument、community norm、norm context、people、people context 与 discussion topic。
  • AI overlay 支持 Extraction、Prioritization、Connecting 与 Presentation；human process 仍负责 Schematize、Build Case 与 Tell Story 的高阶解释。
  • Interpretive work 越高，系统对 raw data 的筛选和重组越强，用户的认知负担下降但 dependence 增加。
  • 风险包括 participant dehumanization、对 legibility 的系统偏差、minority opinion 消失与 false consensus。
  • Safeguards 包括链接原始讨论、给出系统选择 rationale，并把最终 interpretation 留给人。
研究基础与证据边界
维度可核验内容
Empirical basis第一项研究考察 experienced Wikipedians 在无辅助条件下如何阅读复杂讨论；第二项构建 LLM-assisted discussion sensemaking prototype 并研究使用过程。当前论文将二者综合成 design model。
Core mechanism群体 shared history 决定 norms 与 participant signals 的含义；AI 的 prioritization / connection 选择会影响哪些观点进入用户后续 interpretation。
Design tensionHigher interpretive work 减少用户搜索和整理成本，却加大对 system judgment 的依赖。
Evidence limit本文不是新的 causal experiment，也未报告通用 performance estimate；第二项 prototype study 标注为 under review。提出的是 study-informed conceptual framework 与 design agenda。

AcCoRD: Evaluating User-Agent Collaboration Under Realistic User Preference Dynamics

Tejas Srinivasan、Shikib Mehri、Nandita Naik、Anirban Das、William M. Campbell、Jesse Thomason · arXiv 2608.27818

背景及重要性真实 shopping / travel interaction 中，preferences 不一定在开始时完整或静态：用户会在 agent 暴露选项后形成新偏好，也可能因不可行约束而调整或放宽要求。
文章做了什么和怎么做作者建立 AcCoRD-Shop 与 AcCoRD-Travel，各 100 个 scenarios，控制 hard / soft underspecification、unachievable preferences 与 triggered preferences；比较五个 instruction-tuned LLMs 的 ReAct 与 uncertainty-guided prompting。
最简单结论Frontier agents 能完成多数任务，却经常不能满足全部 preferences，尤其难以处理由环境信息触发的新偏好。显式 uncertainty prompt 没有稳定改善，说明问题不是一次性多问几个问题即可解决。
  • Shop 使用 WebShop 的 Amazon-like simulated environment，Travel 使用 TravelGym；每个 domain 有 100 个 controlled scenarios。
  • 五个模型的 Perfect Outcome Rate 均低于 30%，即使 task completion 很高，最终 choice 仍常遗漏至少一个 preference。
  • Hard / soft underspecification 通常表现较好；unachievable 与 triggered preferences 更困难，后者必须先由 agent 暴露相关环境信息才能形成。
  • UncReAct 要求每一步显式判断是否存在 unresolved uncertainty，但总体没有稳定提高 Task Score；较弱模型还可能 over-ask 并耗尽 dialogue budget。
  • 实验使用 LLM user simulator，Shop 的 outcome 也使用 LLM judge；真实用户噪声与新 preference dynamics 可能改变 external validity。
Benchmark design、结果与局限
维度可核验内容
DomainsAcCoRD-Shop 从超过 100 万产品的 WebShop 环境构造 product scenarios；AcCoRD-Travel 从 TravelGym 的 flights、hotels、apartments、car rentals 与 restaurants 构造 2–4 booking tasks。
Preference dynamicsHard underspecification 需直接询问；soft preference 可接受较差 fallback；unachievable preference 需发现不可行并协商；triggered preference 只有 agent 主动展示相关 attribute 后才出现。
ModelsLlama-3.1-70B-Instruct、DeepSeek-V3.2、GPT-4.1、GPT-5.1 high reasoning 与 Claude Sonnet 4.5；比较 ReAct 与 UncReAct。
Controls每 episode 最多 50 environment steps 和 20 dialogue turns；user simulator 固定为 GPT-5.1 并做 consistency checking。Travel outcome 用 deterministic predicates，Shop 用 LLM judge。
Main resultsOutcome scores 主要落在 0.6–0.8，Perfect Outcome Rate 均低于 30%。Claude Sonnet 4.5 总体最强；triggered preferences 在两个 benchmark 中普遍最难。
Reporting caveat正文 rollout-parameter 段写每个 scenario single rollout，而主结果表注写每个 scenario 三次 rollouts，存在内部描述不一致；本报告不据此重算 uncertainty，也不把表格平均值视为 human-subject evidence。

市场含义：Shopping agent 的 preference elicitation 需要 prospective uncertainty：agent 要理解“展示什么选项会触发用户形成什么偏好”，而不是只恢复一个预先存在但未表达的 utility vector。
